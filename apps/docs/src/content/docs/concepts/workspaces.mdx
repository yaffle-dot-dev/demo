## What's a workspace?

A workspace is a directory containing OpenTofu (or Terraform) files. Yaffle runs `plan` and `apply` independently for each workspace.

```toml
[[workspaces]]
path = "infra/network"
environments = ["*"]

[[workspaces]]
path = "infra/compute"
environments = ["*"]
```

Each workspace gets its own state file, runs in its own container, and can have its own variables.

## Multiple workspaces

Most projects have multiple workspaces:

```
repo/
├── infra/
│   ├── network/      # VPC, subnets, security groups
│   ├── database/     # RDS, ElastiCache
│   └── compute/      # ECS, Lambda
└── yaffle.toml
```

```toml
[[workspaces]]
path = "infra/network"
environments = ["*"]

[[workspaces]]
path = "infra/database"
environments = ["*"]

[[workspaces]]
path = "infra/compute"
environments = ["*"]
```

## Dependencies

Workspaces often depend on each other. Your compute layer needs outputs from your network layer.

Yaffle automatically detects dependencies by scanning your OpenTofu files for module references to other workspaces. When workspace A depends on workspace B:

1. B runs first
2. B's outputs become available as a module
3. A runs and can consume B's outputs

<Mermaid chart={`
graph LR
    network --> database --> compute
`} />

<Aside type="tip">
Dependencies are inferred from your OpenTofu code. You don't need to declare them manually.
</Aside>

## Using outputs from other workspaces

Reference another workspace's outputs using the Yaffle module registry:

```hcl
# infra/compute/main.tf
module "network" {
  source = "yaffle.dev/api/registry/your-org/infra--network/yaffle"
}

resource "aws_ecs_service" "app" {
  # Use outputs from the network workspace
  network_configuration {
    subnets         = module.network.private_subnet_ids
    security_groups = [module.network.app_security_group_id]
  }
}
```

The module source follows this pattern:
```
yaffle.dev/api/registry/ORG/WORKSPACE--PATH/yaffle
```

Where `WORKSPACE--PATH` uses `--` as path separator:
- `infra/network` → `infra--network`
- `apps/web/infra` → `apps--web--infra`

## Execution order

Yaffle builds a dependency graph and executes workspaces in the right order:

<Mermaid chart={`
graph LR
    network[network]
    monitoring[network-monitoring]
    database[database]
    compute[compute]
    appconfig[app-config]

    network --> database
    monitoring --> database
    database --> compute
    appconfig --> compute
`} />

Root workspaces (no dependencies) run first, in parallel. Downstream workspaces wait for their dependencies to complete.

## Run lifecycle and approval

When you open a PR or push to a branch, Yaffle executes runs through several stages:

<Mermaid chart={`
stateDiagram-v2
    [*] --> pending: Trigger received
    pending --> planning: Runner acquired
    planning --> waiting_approval: Plan complete
    waiting_approval --> applying: Approved
    waiting_approval --> cancelled: Rejected
    applying --> success: Apply complete
    applying --> failed: Apply error
    planning --> failed: Plan error
    success --> [*]
    failed --> [*]
    cancelled --> [*]
`} />

| Status | Description |
|--------|-------------|
| `pending` | Run is queued, waiting for a runner |
| `planning` | OpenTofu plan is executing |
| `waiting_approval` | Plan complete, awaiting human approval |
| `applying` | Apply in progress (after approval) |
| `success` | Run completed successfully |
| `failed` | Run failed with error |
| `cancelled` | Run was cancelled or rejected |

<Aside type="note">
Preview environments require approval before `apply` runs. Configure auto-approval for specific environments in your `yaffle.toml` if needed.
</Aside>

## Workspace variables

Set variables per workspace:

```toml
[[workspaces]]
path = "infra/compute"
environments = ["*"]
variables.instance_type = "t3.medium"
variables.desired_count = 2
```

Use template variables for environment-specific values:

```toml
[[workspaces]]
path = "infra/compute"
environments = ["*"]
variables.environment = "{{ environment }}"
variables.domain = "{{ environment }}.example.com"
```

## Environment targeting

Control which environments a workspace runs in:

```toml
# Runs in all environments (including previews)
[[workspaces]]
path = "infra/network"
environments = ["*"]

# Only production
[[workspaces]]
path = "infra/production-only"
environments = ["production"]

# Only named environments (not previews)
[[workspaces]]
path = "infra/staging-and-prod"
environments = ["staging", "production"]
```
