Run OpenTofu in isolated pull-request environments, without replacing your production pipeline.

## One platform, full lifecycle

```
PR opened → Plan → Apply preview → Test it → Merge → Clean up preview
```

Yaffle manages transient preview environments. For long-lived environments, either let Yaffle
manage them or keep your existing CI as the owner. Both are supported steady states.

Built on [OpenTofu](https://opentofu.org), the open-source fork of Terraform under MPL 2.0. No BSL licensing concerns—run infrastructure automation without vendor lock-in.

## Simple configuration

```toml
# yaffle.toml
version = 1

[[environments]]
name = "production"

[[environments]]
name = "staging"

[cloud]

[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/main"]
environment = "production"

[[cloud.triggers.github.pull_request]]
branch_patterns = ["*"]

[[workspaces]]
path = "infra"
environments = ["*"]
```

Push to `main` → applies to production when you configure Yaffle to own it.  
Your existing CI may own staging and production instead.  
Open a PR → creates a preview you can actually use.

## Why Yaffle

- **OpenTofu native** — Built on MPL 2.0 licensed OpenTofu, compatible with existing Terraform configs
- **Fits beside existing CI** — Keep customer CI in charge of production, or opt into Yaffle-managed named environments
- **Plus preview environments** — Real infrastructure for every PR, not just plans
- **Works with any provider** — AWS, GCP, Azure, Grafana, Snowflake—if it has a provider, Yaffle runs it
- **Outgrown Atlantis?** — All the PR automation, none of the operational overhead
