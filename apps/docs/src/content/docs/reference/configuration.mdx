Configuration lives in `yaffle.toml` at your repository root.

## Minimal example

```toml
version = 1

[[environments]]
name = "production"

[cloud]

[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/main"]
environment = "production"

[[cloud.triggers.github.pull_request]]
branch_patterns = ["*"]

[[workspaces]]
path = "infra"
environments = ["*"]
```

## Full example

```toml
version = 1

# Named environments
[[environments]]
name = "production"

[[environments]]
name = "staging"

# Push to main → production
[cloud]

[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/main"]
environment = "production"

# Push to staging → staging
[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/staging"]
environment = "staging"

# All PRs create transient previews
[[cloud.triggers.github.pull_request]]
branch_patterns = ["*"]

# Shared infra runs in both environments
[[workspaces]]
path = "infra/shared"
environments = ["production", "staging"]
variables.cloudflare_zone_id = "abc123"

# Production-only workspace
[[workspaces]]
path = "infra/production"
environments = ["production"]

# App infra runs in all environments (including PR previews)
[[workspaces]]
path = "apps/api/infra"
environments = ["*"]
variables.domain = "{{ environment }}.yaffle.dev"

# Publish a curated platform API to selected workspaces across repositories
[[workspaces]]
path = "platform/eks"
environments = ["production", "staging"]

outputs.cluster_endpoint = { visibility = "public", consumers = ["acme:applications:apps/*"] }
outputs.cluster_ca = { visibility = "public", consumers = ["acme:applications:apps/*"] }

# Require approval for production changes
[[cloud.approvals]]
workspaces = ["infra/production", "infra/shared"]
environments = ["production"]
approvers = [
  "github:user:alice",
  "github:team:acme/platform",
]
```

## Reference

### `version`

Always `1`.

```toml
version = 1
```

### `[[environments]]`

Named environments your workspaces can target.

```toml
version = 1

[[environments]]
name = "production"

[[environments]]
name = "staging"
```

PR previews are _transient_ environments—they don't need to be declared.

### `[[cloud.triggers.github.push]]`

Run workspaces when a ref (branch or tag) is pushed.

| Field                  | Description                                                                 |
| ---------------------- | --------------------------------------------------------------------------- |
| `ref_patterns`         | Include globs for full refs (must start with `refs/heads/` or `refs/tags/`) |
| `exclude_ref_patterns` | Optional exclude globs applied after includes                               |
| `environment`          | Which environment to target                                                 |

```toml
version = 1

[[environments]]
name = "production"

[[environments]]
name = "staging"

[[environments]]
name = "release"

# Trigger on branch push
[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/main"]
environment = "production"

[[cloud.triggers.github.push]]
ref_patterns = ["refs/heads/staging/*"]
exclude_ref_patterns = ["refs/heads/staging/archive/**"]
environment = "staging"

# Trigger on tag push
[[cloud.triggers.github.push]]
ref_patterns = ["refs/tags/v*"]
environment = "release"
```

`ref_patterns` uses OR semantics: a push matches if it matches any include pattern and no exclude pattern. Legacy `ref = "refs/heads/main"` remains supported as a shorthand for a single include pattern.

Ref globs use `*` for a single path segment and `**` to match across `/`.

### `[[cloud.triggers.github.pull_request]]`

Create transient previews for PRs.

| Field                     | Description                                           |
| ------------------------- | ----------------------------------------------------- |
| `branch_patterns`         | Include globs for the head branch (`["*"]` = all PRs) |
| `exclude_branch_patterns` | Optional exclude globs applied after includes         |

```toml
version = 1

[[cloud.triggers.github.pull_request]]
branch_patterns = ["*"]
exclude_branch_patterns = ["dependabot/**"]
```

`branch_patterns` uses OR semantics: a PR matches if it matches any include pattern and no exclude pattern. Legacy `branch_pattern = "*"` remains supported as a shorthand for a single include pattern.

### `[[workspaces]]`

OpenTofu directories Yaffle manages. (Terraform directories work too—OpenTofu is fully compatible.)

| Field                         | Description                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `path`                        | Path to OpenTofu/Terraform directory                                                                    |
| `environments`                | Which environments run this workspace                                                                   |
| `automatic_preview_isolation` | Opt into whole-workspace provider-aware isolation for managed transient environments (default: `false`) |
| `variables`                   | Variables to inject                                                                                     |
| `outputs`                     | Optional per-output visibility rules for cross-repo module consumers                                    |

```toml
version = 1

[[workspaces]]
path = "infra/api"
environments = ["*"]
variables.environment = "{{ environment }}"
variables.region = "us-east-1"
```

#### Environments

- `["production"]` — Only runs in production
- `["production", "staging"]` — Runs in both
- `["*"]` — Runs in all environments, including PR previews

#### Automatic preview isolation

Set `automatic_preview_isolation = true` on a workspace with `environments = ["*"]` to opt
into Yaffle's whole-workspace preview isolation contract:

```toml
version = 1

[[workspaces]]
path = "infra/api"
environments = ["*"]
automatic_preview_isolation = true
```

The setting applies only to managed transient environments. Named environments keep their
existing resource configuration and names.

Every managed resource in an opted-in workspace must belong to the transient environment and
be safe for Yaffle to create, replace, and destroy. Shared resources must live in an upstream
named, external, or static workspace and be consumed through authorized outputs or read-only
data sources. Imports, provisioners, `lifecycle.prevent_destroy`, and unsupported or unverified
resources stop before Terraform planning. When provider knowledge needs a user decision, Yaffle
Cloud reports an automatic-isolation review requirement rather than silently bypassing it.
Native `.tf` and `.tofu` sources follow OpenTofu's normal precedence. JSON configuration and
repository-authored override files stop before planning because Yaffle cannot prove the final
materialized configuration while they are present.

The initial verified strategy supports `local_file.filename` with provider
`registry.opentofu.org/hashicorp/local` locked at version `2.5.3`. Yaffle preserves the configured
filename when it is a literal basename or one direct string expression, normalizes the result to
lowercase letters, digits, and hyphens, limits it to 63 characters, and adds a deterministic
environment suffix. Mixed interpolation and path expressions require review. The generated override,
provider lock evidence, and manifest are bound to the immutable execution artifact by SHA-256;
repository files and named-environment execution remain unchanged. Other managed resource and exact
provider-version combinations require review.

#### Variables

Variables are injected as `-var` flags. Use `{{ environment }}` to template the current environment name.
Yaffle persists each run's rendered values as immutable execution inputs. Do not put secrets in
`variables`; use a Yaffle connection or a cloud secret reference and resolve the value at runtime.

```toml
version = 1

[[workspaces]]
path = "infra"
environments = ["*"]

variables.environment = "{{ environment }}"
variables.domain = "{{ environment }}.example.com"
```

#### Outputs

Output sharing is opt-in. Declare every output that another workspace, an Action, a lifecycle hook,
or a shared snapshot may consume. Use `internal` for same-repo consumers and `public` for
allowlisted external consumers.

```toml
version = 1

[[environments]]
name = "production"

[[environments]]
name = "staging"

[[workspaces]]
path = "platform/database"
environments = ["production", "staging"]

outputs.connection_string = { visibility = "public", consumers = ["acme:applications:apps/*"] }
outputs.secret_arn = { visibility = "public", consumers = ["acme:applications:apps/*"] }
outputs.database_name = { visibility = "internal" }
```

`outputs.<name>` fields:

| Field        | Description                                                                      |
| ------------ | -------------------------------------------------------------------------------- |
| `visibility` | `internal` or `public`                                                           |
| `consumers`  | Required for `public`; allowlist of `<org-slug>:<repo-slug>:<workspace-pattern>` |

Rules:

- `internal` outputs are only available to downstream workspaces in the same repo
- `public` outputs are available only to explicitly allowlisted workspaces in other repositories in the same Yaffle org during beta
- cross-organization sharing is unsupported in beta and planned as a post-beta enterprise capability
- same-repo consumers can read only explicitly selected `internal` and `public` outputs
- consumer selectors match Yaffle org slug, repo slug, and workspace path

<Aside type="note">
  Sensitive Terraform values are redacted in viewer APIs and rejected from output modules, Actions,
  lifecycle payloads, and public policies. Store the value in Secrets Manager or SSM, export the ARN
  or name instead, and grant consumers IAM access to read it directly.
</Aside>

### `[[cloud.approvals]]`

Require approval before applying.

| Field          | Description        |
| -------------- | ------------------ |
| `workspaces`   | Paths or globs     |
| `environments` | Which environments |
| `approvers`    | Who can approve    |

```toml
version = 1

[[environments]]
name = "production"

[[cloud.approvals]]
workspaces = ["infra/*"]
environments = ["production"]
approvers = [
  "github:user:alice",
  "github:user:bob",
  "github:team:acme/platform-engineering",
]
```

#### Approver syntax

```
<provider>:<type>:<identifier>
```

| Example                     | Meaning                    |
| --------------------------- | -------------------------- |
| `github:user:alice`         | GitHub user alice          |
| `github:team:acme/platform` | GitHub team @acme/platform |

#### Matching

Multiple approval blocks can match. Approvers are combined. Any single approver can approve.

## Variable templating

Use `{{ }}` in variable values. Yaffle uses [MiniJinja](https://github.com/mitsuhiko/minijinja) syntax.

### Available variables

| Template                 | Description                                    | Example value           |
| ------------------------ | ---------------------------------------------- | ----------------------- |
| `{{ environment }}`      | Environment name                               | `production`, `pr-42`   |
| `{{ environment_kind }}` | `named` or `transient`                         | `transient`             |
| `{{ org }}`              | GitHub organization/owner                      | `acme`                  |
| `{{ repo }}`             | Repository name                                | `infra`                 |
| `{{ workspace_path }}`   | Workspace path                                 | `infra/network`         |
| `{{ branch }}`           | Git branch name                                | `main`, `feature/login` |
| `{{ commit_sha }}`       | Full commit SHA                                | `a1b2c3d4...`           |
| `{{ pr_number }}`        | GitHub PR number (null for every other source) | `42`                    |

### Examples

```toml
version = 1

[[workspaces]]
path = "infra"
environments = ["*"]
variables.env = "{{ environment }}"
variables.bucket = "{{ org }}-{{ repo }}-{{ environment }}"
variables.commit = "{{ commit_sha }}"
```

### Filters

MiniJinja filters are supported:

```toml
version = 1

[[workspaces]]
path = "infra"
environments = ["*"]

variables.branch_slug = "{{ branch | replace('/', '-') }}"
variables.env_upper = "{{ environment | upper }}"
variables.fallback = "{{ pr_number | default('main') }}"
```

### Conditionals

```toml
version = 1

[[workspaces]]
path = "infra"
environments = ["*"]

variables.domain = "{% if environment_kind == 'transient' %}preview-{{ pr_number }}{% else %}{{ environment }}{% endif %}.example.com"
```

## Glob patterns

Globs work in `ref`, `branch_patterns`, `exclude_branch_patterns`, `workspaces`, and `environments`:

| Pattern                | Matches                                                            |
| ---------------------- | ------------------------------------------------------------------ |
| `*`                    | Anything within a single path segment                              |
| `**`                   | Anything, including `/`                                            |
| `refs/heads/feature/*` | `refs/heads/feature/login`, but not `refs/heads/feature/a/b`       |
| `dependabot/**`        | `dependabot/npm_and_yarn/foo`                                      |
| `refs/tags/v*`         | `refs/tags/v1`, `refs/tags/v1.0.0`                                 |
| `infra/*`              | `infra/foo`, `infra/foo/bar` (workspace patterns match across `/`) |
