# Set up IAM access for Yaffle

Create one IAM role in your AWS account for the default setup, or multiple roles if you
want environment isolation, then paste those role ARNs in Yaffle.

## Quick start

<Steps>
1. **In Yaffle, open AWS Connection Setup and copy Step 1 values:**
   - `Yaffle principal ARN`
   - `External ID`
   - `Suggested role name` (editable)

2. **Create the IAM role in AWS using one method:**
   - Terraform (Recommended)
   - CloudFormation
   - AWS CLI

3. **Copy the resulting role ARN** from your method output.

4. **Paste role ARN in Yaffle Step 3** and save the connection.
   </Steps>

<Aside type="note">
Yaffle includes an STS session tag named `environment` on AWS role assumptions
for values like `production`, `staging`, or `pr-42`.

For the default setup, you do not need to add any tag-based conditions. You only
need your trust policy to allow both `sts:AssumeRole` and `sts:TagSession`.

If you use the Terraform bootstrap module on this page, this is already configured
for you. If you write the trust policy yourself, include `sts:TagSession` in the
allowed actions.

</Aside>

## Step 2. Set up IAM access for Yaffle

<Tabs>
  <TabItem label="Terraform (Recommended)">
    Use a small local-state bootstrap stack for first-time setup.

    Create `yaffle-bootstrap.tf`:

    ```hcl title="yaffle-bootstrap.tf"
     module "yaffle_bootstrap" {
       source = "git::https://github.com/yaffle-dot-dev/yaffle.git//infra_modules/public/bootstrap-yaffle/aws?ref=main"

      yaffle_principal_arn = "<paste-from-yaffle-step-1>"
      external_id          = "<paste-from-yaffle-step-1>"
      role_name            = "<paste-or-customize-role-name>"
      environment          = "main"
    }

    output "yaffle_role_arn" {
      value = module.yaffle_bootstrap.role_arn
    }
    ```

    Apply:

    ```bash
    tofu init
    tofu apply
    ```

    This bootstrap is intentionally local-state oriented. You can move/import into your
    long-lived state management later if desired.

    Get role ARN:

    ```bash
    tofu output -raw yaffle_role_arn
    ```

  </TabItem>

  <TabItem label="CloudFormation">
    Create `yaffle-bootstrap.yaml`:

    ```yaml title="yaffle-bootstrap.yaml"
    AWSTemplateFormatVersion: "2010-09-09"
    Description: "Yaffle bootstrap role"

    Parameters:
      YafflePrincipalArn:
        Type: String
      ExternalId:
        Type: String
      RoleName:
        Type: String

    Resources:
      YaffleRole:
        Type: AWS::IAM::Role
        Properties:
          RoleName: !Ref RoleName
          AssumeRolePolicyDocument:
            Version: "2012-10-17"
            Statement:
              - Effect: Allow
                Principal:
                  AWS: !Ref YafflePrincipalArn
                Action:
                  - "sts:AssumeRole"
                  - "sts:TagSession"
                Condition:
                  StringEquals:
                    "sts:ExternalId": !Ref ExternalId

      YaffleAdminAccess:
        Type: AWS::IAM::ManagedPolicy
        Properties:
          Description: "Default broad permissions for Yaffle"
          Roles:
            - !Ref YaffleRole
          PolicyDocument:
            Version: "2012-10-17"
            Statement:
              - Effect: Allow
                Action: "*"
                Resource: "*"

    Outputs:
      RoleArn:
        Value: !GetAtt YaffleRole.Arn
    ```

    Deploy:

    ```bash
    aws cloudformation deploy \
      --stack-name yaffle-bootstrap \
      --template-file yaffle-bootstrap.yaml \
      --parameter-overrides \
        YafflePrincipalArn=<paste-from-yaffle-step-1> \
        ExternalId=<paste-from-yaffle-step-1> \
        RoleName=<paste-or-customize-role-name>
    ```

    Get role ARN:

    ```bash
    aws cloudformation describe-stacks \
      --stack-name yaffle-bootstrap \
      --query "Stacks[0].Outputs[?OutputKey=='RoleArn'].OutputValue" \
      --output text
    ```

  </TabItem>

  <TabItem label="AWS CLI">
    Create trust policy and role:

    ```bash
    cat > trust-policy.json <<'EOF'
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Principal": {
            "AWS": "<paste-yaffle-principal-arn>"
          },
          "Action": [
            "sts:AssumeRole",
            "sts:TagSession"
          ],
          "Condition": {
            "StringEquals": {
              "sts:ExternalId": "<paste-external-id>"
            }
          }
        }
      ]
    }
    EOF

    aws iam create-role \
      --role-name <paste-or-customize-role-name> \
      --assume-role-policy-document file://trust-policy.json

    aws iam attach-role-policy \
      --role-name <paste-or-customize-role-name> \
      --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
    ```

    Get role ARN:

    ```bash
    aws iam get-role \
      --role-name <paste-or-customize-role-name> \
      --query 'Role.Arn' \
      --output text
    ```

## What gets created

Default bootstrap creates one role with:

- Trust policy for your **Yaffle principal ARN**
- Required `ExternalId` condition
- Permission for Yaffle to pass the `environment` STS session tag via `sts:TagSession`
- `AdministratorAccess` permissions

<Aside type="tip">
  The default setup is still a single broad execution role. The session tag is attached
  automatically, but nothing about your access model changes unless you choose to add tag-based
  trust or IAM conditions.
</Aside>

## Optional policy customization

If your org requires least privilege, you can customize policy attachments.
Keep in mind Yaffle still needs all permissions required by your Terraform resources.

## Optional: cross-environment safety guardrails

If you want stronger safety boundaries, you can use Yaffle's `environment` session tag
to keep one environment from mutating another.

Yaffle automatically assumes AWS roles with an STS session tag:

- `environment=production` for a production environment
- `environment=staging` for a named non-main environment
- `environment=pr-42` for preview environments

You can use that tag in both the role trust policy and attached IAM policies.

### Recommended model

- **Protected environment role:** broad access, trust requires a specific environment like `production`
- **General environment role:** broad read access, own-environment writes only, trust rejects the protected environment and uses IAM guardrails for the rest

### Terraform example

```hcl title="yaffle-bootstrap-isolated.tf"
data "aws_iam_policy_document" "yaffle_non_main_guardrails" {
  statement {
    sid         = "DenyWritesOutsideEnvironment"
    effect      = "Deny"
    not_actions = [
      "ec2:Describe*",
      "ecs:Describe*",
      "ecs:List*",
      "route53:Get*",
      "route53:List*",
      "s3:Get*",
      "s3:List*",
    ]
    resources = ["*"]

    condition {
      test     = "StringNotEqualsIfExists"
      variable = "aws:ResourceTag/environment"
      values   = ["&{aws:PrincipalTag/environment}"]
    }
  }

  statement {
    sid    = "DenyCreatesOutsideEnvironment"
    effect = "Deny"
    actions = [
      "ec2:Create*",
      "ec2:RunInstances",
      "ecs:Create*",
      "iam:Create*",
      "iam:Put*",
      "lambda:Create*",
      "rds:Create*",
      "route53:ChangeResourceRecordSets",
      "s3:CreateBucket",
      "s3:PutBucket*",
      "s3:PutObject*",
    ]
    resources = ["*"]

    condition {
      test     = "StringNotEqualsIfExists"
      variable = "aws:RequestTag/environment"
      values   = ["&{aws:PrincipalTag/environment}"]
    }
  }
}

resource "aws_iam_policy" "yaffle_non_main_guardrails" {
  name   = "yaffle-non-main-guardrails"
  policy = data.aws_iam_policy_document.yaffle_non_main_guardrails.json
}

module "yaffle_production" {
  source = "git::https://github.com/yaffle-dot-dev/yaffle.git//infra_modules/public/bootstrap-yaffle/aws?ref=main"

  yaffle_principal_arn    = "<paste-from-yaffle-step-1>"
  external_id             = "<production-external-id>"
  role_name               = "yaffle-assume-role-production-use1"
  environment             = "production"
  required_session_tag_keys = ["environment"]
  required_session_tag_equals = {
    environment = "production"
  }
}

module "yaffle_other_environments" {
  source = "git::https://github.com/yaffle-dot-dev/yaffle.git//infra_modules/public/bootstrap-yaffle/aws?ref=main"

  yaffle_principal_arn    = "<paste-from-yaffle-step-1>"
  external_id             = "<other-environments-external-id>"
  role_name               = "yaffle-assume-role-other-envs-use1"
  environment             = "shared"
  required_session_tag_keys = ["environment"]
  required_session_tag_not_equals = {
    environment = "production"
  }
  managed_policy_arns = [
    "arn:aws:iam::aws:policy/AdministratorAccess",
    aws_iam_policy.yaffle_non_main_guardrails.arn,
  ]
}
```

<Aside type="note">
  If you prefer a permissions boundary instead of explicit deny policies, pass
  `permissions_boundary_arn` to the bootstrap module and keep the same session-tag trust rules.
</Aside>

You can substitute any protected environment name here, not just `production`.
The important pattern is that Yaffle supplies the session tag and your trust/policy
logic decides whether that tag should be unrestricted, pinned to one environment,
or used to compare against resource tags.

### In Yaffle

Create separate AWS connections for each role:

- **Protected environment connection:** scoped to `production` (or your chosen protected environment), uses the matching role ARN and external ID
- **General environments connection:** scoped to `staging`, `pr-*`, or any other environments, uses the second role ARN and external ID

Use the same workspace scopes on both connections unless you intentionally want different coverage.
